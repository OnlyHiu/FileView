# FileView v0.2.0 需求计划

> 目标：以 Notepad++ 的操作逻辑为基准，重构 FileView 的信息架构与视觉表现，解决「设置页覆盖文本区」「编辑器 / 查看器割裂」「格式支持偏少」三个问题，并让整体观感优于 Notepad++。

---

## 1. 现状问题（用户反馈）

| # | 问题 | 现象 | 根因 |
|---|---|---|---|
| P1 | 点击「设置」后覆盖文本显示区域 | 设置界面压在文档内容之上，半透明背景与正文叠在一起，看不清、也回不去 | 设置页与文档区共用同一个 `<main>` 容器，且窗口为透明窗格、底色 `--smoke-bg` 为半透明色 |
| P2 | 编辑器与查看器存在硬分界 | 「视图」菜单在 查看器 / 编辑器 之间二选一，工具栏还要再放一组「树形/表格/原始」切换，默认打开不是文本 | `page` 状态把 `editor` 与 `viewer` 做成了互斥页面，`SegmentedControl` 出现在工具栏右侧 |
| P3 | 格式化操作散落在工具栏 | 格式化、压缩、键排序三个 JSON 专用按钮占据工具栏中段 | 工具栏直接挂载了 `applyFormat/applyMinify/applySort` |
| P4 | 支持的文件格式偏少 | 仅 JSON 家族 / MD / INI / txt / log，代码文件、YAML、CSV、XML 等打开后只有纯文本 | `FileKind` 只有 4 类，`EXT_KIND` 表极短，Rust 端 `SUPPORTED_EXTS` 同步受限 |
| P5 | 观感与操作细节 | 工具栏图标含义模糊、标签栏与状态栏偏朴素，缺少 Notepad++ 的关键操作（查找、撤销、面板开合） | 组件层缺少面板容器、查找栏、历史栈 |

## 2. v0.2.0 目标形态

```
┌────────────────────────────────────────────────────────────────────────────┐
│ 标题栏  图标 · 名称 · 当前文件路径                             ─ □ ✕      │
├────────────────────────────────────────────────────────────────────────────┤
│ 菜单栏  文件 编辑 搜索 格式化 视图 设置 帮助                                  │
├────────────────────────────────────────────────────────────────────────────┤
│ 工具栏  新建 打开 保存 │ 查找 撤销 重做 │ 查看工具 分离窗口 │ 解析模式        │
├────────────────────────────────────────────────────────────────────────────┤
│ 标签栏  [ 未命名 ][ data.json ● ][ readme.md ] +                            │
├───────────────────────────────────────────────┬────────────────────────────┤
│                                               │ 工具面板（可开合 / 可拖宽） │
│  文档区：恒为文本 / 源码（行号 + 语法高亮）      │  ┌ 树形 表格 原始 预览 结构 ┐ │
│  ↕ 查找栏（Ctrl+F 就地浮出）                   │  │ 内容 …                    │ │
│                                               │  └──────────────────────────┘ │
├───────────────────────────────────────────────┴────────────────────────────┤
│ 状态栏  ● 合法 · 9 节点 · 深度 2 · 90 B · 0 ms        UTF-8 · Ln 1, Col 1   │
└────────────────────────────────────────────────────────────────────────────┘
```

核心原则：

1. **文档区唯一**：文档区永远显示当前文件的文本（可编辑），不再有「编辑器 / 查看器」二选一。
2. **工具面板化**：树形 / 表格 / 原始 / 预览 / 结构 / 查询 / 设置全部收进右侧可关闭面板，文档区始终可见可编辑。
3. **默认即文本**：启动、打开文件、双击标签都进入文本视图；查看工具是需要时才打开的工具。
4. **格式操作归位**：格式化 / 压缩 / 键排序 / 解析模式统一收进「格式化」菜单，工具栏只留高频动作。
5. **多格式一等公民**：扩展名 → 文件大类 → 高亮 → 专用视图 → 文件关联，整链路打通。

## 3. 功能需求

### 3.1 布局与面板（对应 P1、P2）

- **FR-1 停靠面板**：右侧面板宽度可拖拽调整（最小 320px / 最大 70%），默认 460px；面板有独立不透明背景（`--smoke-bg-layer`），不与文档叠色。
- **FR-2 面板开合**：`查看工具` / `查询` / `设置` 三个入口互斥开关；面板标题栏右侧「×」关闭；`Esc` 关闭当前面板；再次点击菜单项即关闭（toggle）。
- **FR-3 文档区常驻**：切���面板不清空文档、不丢失光标与滚动位置。
- **FR-4 查找栏**：`Ctrl+F` 在文档区顶部浮出查找栏（输入 / 上一个 / 下一个 / 匹配计数 / 区分大小写 / 替换入口占位），`Enter` 跳到下一处并选中，`Esc` 关闭。查找与 JSONPath 查询分离：`Ctrl+F` = 文档查找，`Ctrl+Shift+F` = 格式化，`Ctrl+G` = JSONPath 查询。
- **FR-5 撤销 / 重做**：编辑历史栈（最多 200 步，600ms 内连续输入合并为一���），`Ctrl+Z` / `Ctrl+Y`。

### 3.2 菜单与工具栏（对应 P3）

| 菜单 | 条目 | 快捷键 |
|---|---|---|
| 文件 | 新建 / 打开 / 保存 / 另存为 / 关闭标签 / 最近文件 / 分离为独立窗口 / 退出 | `Ctrl+N` `Ctrl+O` `Ctrl+S` `Ctrl+Shift+S` `Ctrl+W` |
| 编辑 | 撤销 / 重做 / 查找 / 复制全部内容 / 复制文件路径 | `Ctrl+Z` `Ctrl+Y` `Ctrl+F` |
| 搜索 | 文档内查找 / JSONPath 查询 | `Ctrl+F` `Ctrl+G` |
| 格式化 | 格式化 JSON / 压缩 JSON / 键排序 / 转义字符串 / 反转义字符串 / 解析模式（严格·JSONC·JSONL） | `Ctrl+Shift+F` |
| 视图 | 查看工具面板 / 树形 · 表格 · 原始 · 预览 · 结构 / 深色模式 / 放大 · 缩小字号 | `Ctrl+B` |
| 设置 | 设置面板 | |
| 帮助 | 关于 FileView | |

- 工具栏只保留：新��、打开、保存 │ 查找、撤销、重做 │ 查看工具、分离窗口 │（JSON 时）解析模式下拉。**不再出现格式化 / 压缩 / 键排序按钮。**

### 3.3 多格式支持（对应 P4）

- **FR-6 大类扩展**：`FileKind` 扩展为 `json | markdown | ini | yaml | toml | csv | xml | html | code | text`。
- **FR-7 扩展名映射**：新增 YAML/TOML/CSV/TSV/XML/HTML/CSS/SCSS/JS/TS/JSX/TSX/Python/Ruby/PHP/Java/Kotlin/Swift/Rust/Go/C/C++/C#/Lua/Shell/PowerShell/SQL/Properties/.env 等。
- **FR-8 高亮**：新增通用 C 家族高亮（行注释 / 块注释 / 字符串 / 数字 / 关键字 / 内置常量 / 函数名 / 类型名），以及 YAML / TOML / XML / HTML / CSV 专用高亮。
- **FR-9 专用视图**：CSV/TSV → 表格视图（支持引号转义与分隔符自动识别）；YAML/TOML → 键结构视图；XML/HTML → 结构化标签树（简化）；Markdown → 预览 + 源码；INI → 结构视图。
- **FR-10 打开对话框与文件关联**：`SUPPORTED_EXTS` 与 Rust 端 `file_assoc::SUPPORTED_EXTS` 同步扩展；设置页按类别分组展示复选项。

### 3.4 视觉升级（对应 P5）

- 标题栏 / 菜单栏 / 工具栏 / 标签栏 / 状态栏按 Notepad++ 骨架重排，尺寸与留白统一（h-32 / h-28 / h-40 / h-36 / h-24 节奏）。
- 标签页：激活态用顶部 2px 强调条 + 圆角上角 + 独立底色，未激活更淡；关闭按钮常显于激活标签。
- 工具栏：图标按钮统一 32×32、圆角 6px、悬停高亮、分组间 1px 分隔线。
- 状态栏：左「语法合法性 + 统计」，中「状态消息」，右「路径 / 行列 / 编码 / 类型」。
- 配色：延续 Fluent 变量体系，补充 `--syn-func`、`--syn-type`、`--syn-keyword` 等语义色，明暗两套均调优。

## 4. 技术方案

| 领域 | 方案 |
|---|---|
| 状态 | `jsonStore` 中 `page: "editor" \| "viewer" \| ...` 改为 `panel: "none" \| "viewer" \| "query" \| "settings"`；新增 `find*`、`undo/redo` 状态 |
| 面板 | 新增 `components/SidePanel.tsx`（头部 + 可拖拽分隔条 + 内容区）；`features/QueryPanel.tsx`、`features/SettingsPage.tsx` 改为面板内自适应宽度 |
| 编辑器 | `features/SourceEditor.tsx` 增加 `ref` 暴露 `revealOffset(offset, length)` 供查找跳转；行号槽支持当前行高亮 |
| 高亮 | `lib/highlight.ts` 新增 `tokenizeCode`（C 家族通用）与 `tokenizeYaml/Toml/Xml/Html/Csv` |
| 表格 | 新增 `features/CsvView.tsx`（CSV/TSV 解析 + 虚拟化表格复用） |
| 结构 | 新增 `features/KeyValueView.tsx`（YAML/TOML 键路径树） |
| 后端 | 仅扩展 `sys::file_assoc::SUPPORTED_EXTS` 与注册描述；其余命令复用 |
| 版本 | `package.json`、`Cargo.toml`、`tauri.conf.json`、关于对话框、设置页同步升级至 `0.2.0` |

## 5. 验收标准

1. 点击「设置」不再覆盖文本：面板独立、不透明、可关闭（× / Esc / 菜单切换），关闭后文档区原样保留。
2. 启动与打开文件后默认显示文本（源码）视图；树形/表格等只在「查看工具」面板中出现。
3. 工具栏不再出现格式化 / 压缩 / 键排序按钮，三者仅在「格式化」菜单中可用。
4. `.md/.yaml/.toml/.csv/.xml/.html/.js/.py/.rs/.go/...` 等文件打开后有正确高亮，CSV 有表格视图，MD 有预览。
5. `Ctrl+F` 查找栏可用并能跳转高亮；`Ctrl+Z` 可撤销。
6. 版本号显示 0.2.0，安装包名 `FileView_0.2.0_x64-setup.exe`。
7. `npm run build` 与 `npm run tauri:build` 均通过，无 TS 报错。
