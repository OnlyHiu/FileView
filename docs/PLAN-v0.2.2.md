# FileView v0.2.2 需求计划

> 目标：修复「部分 Markdown 文件无法正确形成换行分行显示」与「选中文字虚影重叠」两个用户可见缺陷，
> 同时把版本控制文档（PLAN / RELEASE / AUDIT / CHANGELOG）补齐成可持续维护的结构。

---

## 1. 现状问题（用户反馈）

| # | 问题 | 现象 | 根因 |
|---|---|---|---|
| P1 | Markdown 预览无法正确换行分行 | 文档中的引用块（`>`）被整体压成一段：标题、列表条目全部挤在同一行；引用块里的 `-` 列表项退化成普通文本 | `renderMarkdown()` 把连续的引用行 `quote.join(" ")` 后作为**单个段落**输出；引用块内部**不递归解析**，列表 / 代码块 / 空行分段全部丢失 |
| P2 | 行尾两空格的硬换行失效 | 源文件里刻意换行的句子在预览中仍连成一段 | 段落行一律 `join(" ")`，硬换行标记被丢弃 |
| P3 | 相对链接全部失效 | `[README.md](README.md)` 的 `href` 变成 `#`，点击无反应 | `safeUrl()` 的相对路径正则只接受 `#` / `/` / `./` / `../`，`README.md` 这类同目录路径被判定为不安全并降级为 `#` |
| P4 | 链接地址里的 `&` 被双重转义 | `?a=1&b=2` 渲染成 `?a=1&amp;amp;b=2`，链接实际指向错误地址 | 行内文本先 `escapeHtml`、再把已转义的地址交给 `safeUrl()` 又 `escapeAttr` 一次 |
| P5 | 选中文字出现「虚影重叠」 | 选中一段文字后，选中区域里出现两重叠影的文字 | 编辑区是「透明 textarea + 语法高亮层」叠加；选中时浏览器按系统 `::selection` 用**不透明前景色**重绘选中文字，与下方高亮层的文字重叠 |
| P6 | 含 Tab 的文件横向错位 | 高亮层与编辑层的列宽不一致，Tab 之后的内容出现错位重影 | 高亮层未设 `tab-size`（默认 8），编辑层写死 `tabSize: 2` |
| P7 | 版本控制文档缺失 | `docs/` 下只有 v0.2.0 的三件套，v0.2.1 无任何文档，版本演进不可追溯 | 每版文档靠临时补写，没有索引与写作规范 |

## 2. v0.2.2 目标形态

```
┌───────────────────────────────────────────────────────────────┐
│ 文档区（始终是文本）                                            │
│ ┌────────┬──────────────────────────────────────────────────┐ │
│ │ 行号   │ 透明编辑层 (textarea)                             │ │
│ │        │   └ 语法高亮层（绝对定位，跟随滚动）              │ │
│ └────────┴──────────────────────────────────────────────────┘ │
│                     ▲ 选中时：文字保持透明，只画选中底色        │
├───────────────────────────────────────────────────────────────┤
│ 查看工具面板                                                  │
│ ┌───────────────────────────────────────────────────────────┐ │
│ │ # 08 里程碑与交付物                                        │ │
│ │ ┌───────────────────────────────────────────────────────┐ │ │
│ │ │ 新手导读                                               │ │ │  ← 引用块内分段
│ │ │ • 适合谁：……                                          │ │ │  ← 引用块内列表
│ │ │ • 要不要通读：……                                      │ │ │
│ │ └───────────────────────────────────────────────────────┘ │ │
│ └───────────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────┘
```

核心原则：

1. **结构保真**：Markdown 的行与块结构必须如实呈现，不能为了「少写几个分支」
   而把引用块、列表、硬换行统统压成一行。
2. **两层一致**：编辑区的两层（透明编辑层 / 语法高亮层）必须在
   字体、行高、制表位、选中渲染上完全一致，否则必然出现重影。
3. **文档可持续**：每个版本三件套齐备 + 全局索引 + 写作规范。

## 3. 功能需求

### 3.1 Markdown 渲染（对应 P1、P2、P3、P4）

- **FR-1 引用块递归解析**：引用块内容交给独立的块级解析器处理，
  其内部的段落、空行分段、列表（含嵌套）、代码块、Setext 标题全部保留。
- **FR-2 引用块按源文件分行**：引用块常被当作「提示框」，一行一条说明；
  因此块内**保留源文件的换行**（`<br />`），不按 CommonMark 的软换行合并。
- **FR-3 硬换行**：行尾两个以上空格或反斜杠 → `<br />`；软换行仍合并为一段。
- **FR-4 列表结构**：缩进嵌套列表、任务列表（`- [ ]` / `- [x]`）、
  有序 / 无序列表切换均正确渲染。
- **FR-5 Setext 标题**：`===` / `---` 下划线式标题被识别为 `h1` / `h2`。
- **FR-6 反斜杠转义**：`\*`、`\_`、`\[` 等按原样输出，不被强调规则误伤。
- **FR-7 行尾规范化**：CRLF / CR 统一为 LF，去掉 BOM；段落 / 列表中不再残留 `\r`。
- **FR-8 相对链接可用**：`README.md`、`docs/START-HERE.md` 等保留有效 `href`；
  `javascript:` / `data:` / `vbscript:` / 协议相对地址 `//host` 一律拦截。
- **FR-9 链接地址只转义一次**：`&` 只转义一次，不得出现 `&amp;amp;`。
- **FR-10 表格识别更严格**：分隔行的列数必须与表头一致。

### 3.2 编辑器选中与对齐（对应 P5、P6）

- **FR-11 选中不重影**：`::selection` 强制选中文字保持透明（`color` +
  `-webkit-text-fill-color`），只保留半透明选中底色，
  高亮层文字透过底色正常显示。
- **FR-12 制表位一致**：高亮层容器与编辑层共用同一个 `tab-size`
  （取自缩进设置：`2` / `4` / `tab`）。
- **FR-13 深浅色适配**：选中底色随主题切换。

### 3.3 版本控制文档（对应 P7）

- **FR-14 文档索引**：`docs/README.md` 列出全部文档与用途。
- **FR-15 变更日志**：`docs/CHANGELOG.md` 汇总各版本变更，作为版本控制的唯一索引。
- **FR-16 版本三件套齐备**：v0.2.2 的 PLAN / RELEASE / AUDIT 齐备；
  补齐缺失的 v0.2.1 发行说明。
- **FR-17 写作规范**：文件名、文档头、结论先行、可验证、交叉引用、不夸大。
- **FR-18 发版检查清单**：版本号四处一致 + README 下载链接 + 文档齐备。

### 3.4 版本升级（对应发布）

- **FR-19 版本号**：`package.json` / `Cargo.toml` / `tauri.conf.json` /
  `Cargo.lock` / `src/App.tsx` 的 `APP_VERSION` / README 下载链接
  全部升级为 `0.2.2`。

## 4. 技术方案

| 领域 | 方案 |
|---|---|
| Markdown | `src/lib/markdown.ts` 重构：抽出 `renderBlocks(lines, opts)` 作为统一块级解析器；引用块内容递归调用；行内渲染引入硬换行哨兵 `\u0002` 与转义占位符 |
| 链接安全 | 拆分 `isSafeUrl()`（判定）与 `safeUrl()` / `inlineUrl()`（转义），避免已转义文本被二次转义 |
| 选中渲染 | `src/styles/index.css` 新增 `.editor-surface::selection` 规则；编辑层 textarea 加 `editor-surface` 类 |
| 制表位 | `SourceEditor` 依据 `indent` 设置计算 `tabSize`，同时应用于高亮层容器与 textarea |
| 文档 | 新增 `docs/CHANGELOG.md`、`docs/README.md`、`docs/RELEASE-v0.2.1.md`、`docs/PLAN-v0.2.2.md`、`docs/RELEASE-v0.2.2.md`、`docs/AUDIT-v0.2.2.md` |

## 5. 验收标准

1. `> **标题**` + `>` + `> - 条目` 形式的引用块在预览中分段显示，条目渲染为列表项。
2. 行尾两空格的段落按源文件分行；软换行仍合并为一段。
3. 缩进嵌套列表、任务列表、Setext 标题正确渲染。
4. `[README](README.md)` 的 `href` 为 `README.md`（不再是 `#`）；
   `javascript:` 链接仍被拦截。
5. `?a=1&b=2` 的链接地址不被双重转义。
6. CRLF 文件渲染后不含 `\r`。
7. 在文档区选中文字时，选中区域只出现一层文字（无虚影），底色可见。
8. 含 Tab 的文件，编辑层与高亮层列宽一致，无横向错位。
9. `npm test` 全部通过（新增 Markdown 结构回归用例）。
10. `npm run build` 与 `npm run tauri:build` 通过，无 TS 报错。
11. 版本号在 6 处（package.json / Cargo.toml / tauri.conf.json / Cargo.lock /
    APP_VERSION / README）全部为 `0.2.2`。
12. `docs/` 下 v0.2.2 三件套齐备，`CHANGELOG.md` 含 v0.2.2 小节。
